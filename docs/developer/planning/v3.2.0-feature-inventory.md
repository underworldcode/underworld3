# Underworld3 v3.2.0 — feature inventory

Draft for review by @lmoresi and the Steering Committee. **Not the manifest** — a proposal for what
v3.2.0 should announce and at what level.

Method: all 186 PRs merged into `development` since v3.1.0 (8 Jul 2026) were clustered into features
from their PR bodies and changed-file lists, not their titles. Tests were attributed via each PR's
changed files, then a second pass opened every cited test and docs page to refute misattributions
(35 were removed this way). 12 of 21 features got that second pass before the run was cut short;
those are marked in the Verified column.

TRL rule used: collected `tier_a`/`tier_b` tests → 4; plus a user-facing docs page **and** a runnable
demonstration → 6. Supported = TRL 6+, Preview = 4–5, In development = ≤3.

## Parallel coverage — the significant gap

UW3 is an MPI code, but MPI tests live only in `tests/parallel/`, and only files named `test_*.py`
are ever collected. Files named `ptest_*.py` exist on disk, may carry tier markers, and **never run**.

| Situation | Features |
|---|---|
| MPI tests run in CI | `curved-boundary-conditions`, `data-access-array-contract`, `fmg`, `checkpoint-restart`, `navier-stokes-supg`, `interpolation-and-evaluation`, `parallel-robustness`, `boundary-flux-recovery`, `mesh-adaptation`, `jit-compilation`, `geoid-postprocessing` |
| MPI tests exist but **never run** (`ptest_`) | `fault-networks`, `solver-control-and-reporting` |
| No MPI tests at all | `analytic-solutions`, `materials-system`, `stress-visualisation`, `mesh-smoothing`, `transport-histories`, `constitutive-models`, `free-surface`, `containers-and-hpc-builds` |

39 MPI test files are collected across the features; **23 more are `ptest_` and never execute**.
`fault-networks` is the worst case: its entire parallel contract is 12 files, none of which run —
which is why it is Preview rather than Supported despite having the most complete docs of any feature.

Two mitigations found on 2026-09-24, both verified by experiment:

1. **Ordinary `tier_a`/`tier_b` tests run under `mpirun` unmodified.** 18 files / 603 tests of
   `analytic-solutions`, `materials-system` and `stress-visualisation` passed at 2 ranks with no
   code changes. The plumbing was never the obstacle — `pytest-mpi` runs unmarked tests under
   `--with-mpi`, `conftest.py` is rank-neutral, `pytest.ini` does not interfere. They were simply
   never run that way, because `test_levels.sh --parallel` points `mpirun` only at `tests/parallel/`.
2. **At 4 ranks, 3 tests in `test_0071_index_swarm_proxy_location.py` fail** — and the failures are
   test bugs, not product bugs. Each asserts an *existential* claim against rank-local data
   (e.g. line 80, `results["nodes"] > 1e-2`: 'some node is visibly wrong', true globally, false on
   a rank whose subdomain misses the material interface). The companion assert on line 79,
   `max < tol`, is decomposition-safe: a universal claim holds locally exactly when it holds
   globally. The fix is one MPI reduction per assert.

So the honest reading is not 'the features have no parallel tests' but: **the code survives
decomposition; the test suite's coverage of that fact is thin, and some tests assert in a shape
that cannot survive it.**

## 4-rank verification results (2026-09-24)

Every category above was run at `mpirun -n 4` with `--timeout=600`. Three distinct issues surfaced,
of three different kinds; none blocks the release.

| Category | Result at 4 ranks | Nature |
|---|---|---|
| Ordinary `tests/*.py` of the three features with no MPI tests (18 files) | **587 / 590 pass** | 3 failures, all in `test_0071` |
| Existing MPI suite `tests/parallel/test_*.py` (42 files) | **157 pass, 1 fail** | the failure is *not* a parallel defect |
| The 16 genuine `ptest_` files, never executed before (60 tests / 99 parametrised) | **99 pass, 1 hang** | **a real parallel bug** |

**1. `test_0071_index_swarm_proxy_location.py` — 3 test bugs.** Each asserts an *existential*
claim against rank-local data, e.g. line 80 `results["nodes"] > 1e-2` ("some node is visibly
wrong") — true globally, false on a rank whose subdomain misses the material interface. Line 79 of
the same test (`max < 1e-5`, a *universal* claim) is decomposition-safe. Rule: `∀` survives
decomposition, `∃` needs an MPI reduction. One reduction per assert fixes it. Product code is fine.

**2. `test_1063_constrained_freeslip_parallel.py::…[ti]` — an accuracy regression, not parallel.**
Partition independence *passed*; the `accuracy_anchor` assertion failed: mean-stripped topography
**37.078 recorded → 37.753 now (+1.8 %, rtol 1 %)** on an identical mesh. Reproduced exactly at
2 ranks, so it is rank-count-independent. `iso` passes; only `ti`. This is the second independent
signal this quarter that the transverse-isotropic path is unsettled — the first being the stale
`# TODO(BUG)` at `src/underworld3/constitutive_models.py:2986` (issue #457, claimed fixed by #493).
Supports keeping `constitutive-models` at Preview.

**3. `ptest_0844_reconnect_parallel.py::test_adapt_with_repair_runs_in_parallel` — a genuine
parallel bug.** Hangs in `uw.mpi.comm.allreduce` (`_global`, line 174): some ranks enter the
collective, others do not. Found only because these files were run for the first time. The rest of
the fault-network parallel contract — `line_cut`, `place_sheet`, `place_thin_volume`,
`remove_embedded`, `fault_split`, the 3D network files — **passes at 4 ranks**.

That last result changes the reading of `fault-networks`: its parallel contract is not unknown, it
is *largely working with one identified defect*. Preview remains right, but for a specific,
fixable reason rather than an absence of evidence.

## Three findings for @lmoresi

1. **The existing `mesh-adaptation` manifest entry is mis-scoped.** Its `validation.paths` name tests
   that exercise `mesh.remesh()` (the MMG remesher) and hand-built multigrid hierarchies — not
   `adapt()`. One listed path, `tests/test_0760_mesh_ot_adapt.py`, no longer exists and is silently
   dropped by `_expand_paths`. The entry has been passing for the wrong reason.
2. **Composite features announce at their weakest part.** `fault-networks`, `transport-histories` and
   `constitutive-models` each bundle one sub-capability at TRL 6 with others at 3–4. Either split the
   keys (the schema's `select:` already allows it) or accept the lower band.
3. **`fault-networks` parallel contract does not run.** 12 `ptest_` files. Renaming them to `test_*`
   is a one-line config change plus whatever they then reveal.
